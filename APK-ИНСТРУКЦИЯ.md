По нажатию APK скачивается с прогрессом и ставится через системный установщик (Android покажет одно окно «Установить» — пропустить его нельзя), после установки новая версия открывается сама.

- **Файл:** [ProkatInstrumenta-10.13.apk](ProkatInstrumenta-10.13.apk), `ProkatInstrumenta.apk` — тот же файл для старых ссылок.

- SHA-256 файла: `1af9e0c0f06bfb83f7f2e4dd78bd2730518e8a12e80c32e47a6d1b8177da75a7`, размер 1103945 байт.
- Сертификат тот же, что у 10.12-clone (`4a70cc4f…`): **ставится поверх 10.12 без удаления**. Проверка `apksigner verify` пройдена.
- Как собрано: в `onCreate` после `profVer.setText` добавлены 2 инструкции smali (вызов `SelfUpdate.bind`); сам модуль (`ru.prokatnvsk.app.SelfUpdate` + 2 receiver) лежит в `classes2.dex`; в манифест добавлены receiver'ы. ## Как выпускать следующие обновления (10.14+)

1. Собери новый APK (тот же пакет, `versionCode` +1, подпись **тем же** `prokat-new.p12` — иначе поверх не встанет).
2. Положи файл в корень сайта, обнови ссылки/баннер/тесты на новое имя (см. коммит 10.13 как образец).
3. Обнови [app-update.json](app-update.json): `versionCode`, `versionName`, ссылку `apk`.
4. Всё: у всех пользователей на 10.13+ в Профиле сама появится кнопка обновления.

> Старые версии (10.12 и ниже) кнопки не имеют — им нужно один раз вручную поставить 10.13+, дальше обновления идут из приложения.

## ⚠️ Подпись изменилась — обновление поверх невозможно

Оригинальный keystore (`android-app/prokat.keystore`, сертификат `6d077…606`, см. запись с доступами) не был доступен на момент сборки, поэтому APK подписан **новым** ключом. Android **не установит** 10.12 как обновление поверх любой предыдущей версии (10.11 recovery и ранее).

**Установка:** удалите старое приложение → скачайте APK → установите → войдите в аккаунт. Данные учётной записи и заявки хранятся на сервере и не пропадут; локальные черновики при удалении могут исчезнуть.

Новый keystore хранится вне репозитория (файл выложен владельцу в рабочую папку): alias `prokat`, пароль `prokat2026`, SHA-1 файла `d8df7536d5ca5788304ca966b34a4b59eb2c0501`. **Не публиковать в GitHub.** Все последующие сборки подписывать им же.

Если оригинальный keystore из `android-app_golden.tar.gz` будет предоставлен, эту же сборку можно переподписать им — тогда 10.12 встанет поверх 10.11 без удаления.

## Как собран APK

Без исходников использована точечная правка байт-кода:

1. `apktool d` → правка `MainActivity.smali` (`saveSession`: +`iput-object v0, p0, ->userEmail` после вычисления e-mail) и `apktool.yml` (`versionCode 86`, `versionName 10.12`).
2. `apktool b` (aapt2) → `zipalign` → `apksigner sign` (новый keystore).
3. Контроль: повторный `baksmali` подтвердил наличие патча в финальном APK; `apksigner verify --print-certs` — подписи v1/v2/v3 валидны.

Пересборка с новым ключом (файл `-clone`, тот же код 1-в-1): снятие старой подписи (3 файла META-INF + блок v2/v3) → выравнивание zip → подпись `prokat-new.p12` (v1+v2+v3). Контроль: контент 83/83 файлов совпал с 10.12 (отличается только сертификат), `apksigner verify` — все схемы true, манифест: пакет `ru.prokatnvsk.app`, 86/10.12, sdk 21/34.
