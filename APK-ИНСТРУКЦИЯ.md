## Важно про 10.15 (первая версия на новом ключе)
Android ставит обновление «поверх» только с тем же ключом. 10.15 подписана другим ключом, поэтому:
- у тех, у кого стоит 10.12–10.14, кнопка «Обновить» выдаст «Приложение не установлено»;
- нужно **один раз удалить приложение и поставить 10.15 с сайта**. Аккаунт, заявки, инструменты, отзывы и избранное хранятся на сервере и не пропадут; войти нужно заново;
- старая 10.14 продолжает работать (сервер общий), переустановка нужна ради новых исправлений;
- при выпуске 10.15: на сайте заменить «ставится поверх, удалять не нужно» на «удалите старую версию и установите новую» (app.html, admin.html, chief.html, assets/app.js); `app-update.json` до 89 не поднимать, пока у пользователей 10.14 (их кнопка обновления не сработает) — поднять при 10.16, когда базой станет 10.15;
- с 10.15 и дальше обновления снова идут «поверх» (ключ №6).

## Как выпускать версию (с 10.15)
1. Сборка: apktool decode предыдущей версии → правки smali → versionCode +1 → сборка → zipalign → **apksigner с ключом №6 из секретов GitHub** (`ANDROID_KEYSTORE_B64`, `ANDROID_KEYSTORE_PASS`). Ключ никогда не скачивается на чужие компьютеры и не попадает в репозиторий.
2. Проверка: `apksigner verify --print-certs` → сертификат = эталон из `docs/КЛЮЧ-ПОДПИСИ.md`; aapt → новый versionCode.
   В песочнице агента Java нет — там работает `python3 tools/apk-verify.py <файл.apk> [эталон-sha256]`
   (нужны `androguard` и `cryptography`): сертификат, подпись v2 ключом сертификата, дайджесты всех записей,
   выравнивание `resources.arsc`, CRC. Входит в `tools/check.sh` как раздел 4.4 (без пакетов честно пропускается).
3. Сайт: положить `ProkatInstrumenta-<версия>.apk` в корень; обновить ссылки (account.html, admin.html, app.html, chief.html, assets/app.js — `APP_DOWNLOAD_URL`, `APP_RELEASE_ID`), тесты (`tests/app-banner.cjs`, `tests/chief-and-apk.cjs`, `tests/syntax-and-release.cjs`), `ProkatInstrumenta.apk` = копия новой версии.
4. `app-update.json`: `versionCode`, `versionName`, `apk`/`apkUrl`, `notes`.
5. Предыдущий APK убрать из корня (сторож `tests/keystore-check-guard.cjs` не пропустит APK, на который нет ссылок, — чтобы не путаться). В истории git он останется.

6. Ссылки на страницах НЕ менять: их подставляет `assets/app-release.js` (атрибут `data-app-dl`). Новую версию для всех выпускает создатель кнопкой «Подтвердить релиз».

## Релиз через кнопку «Подтвердить релиз» (решение владельца №23, 05.10.2026)
- **Создатель** — `eclips.ru@mail.ru`. Только у него, только на телефоне, в кабинете (account.html, chief.html) две карточки:
  - сверху **кислотно-жёлтая** «Новая версия X — видна только вам»: «Скачать X» и «✅ Подтвердить релиз»;
  - ниже **кислотно-зелёная** «Сейчас у всех пользователей» — выпущенная версия.
- **Все остальные** (и создатель на компьютере) видят одну ссылку — на выпущенную версию: баннер сверху на **10 секунд** + зелёная карточка в кабинете.
- **Выпущенная версия** = последняя строка таблицы `public.app_releases` (миграция `supabase/migrations/20261005_app_releases.sql`). Пока строк нет или база недоступна — у всех `IVA_RELEASE_FALLBACK` в `assets/app-release.js` (сейчас **10.14**).
- «Подтвердить релиз» добавляет строку; база примет её **только** от eclips.ru@mail.ru (политика RLS). Ссылка — только на APK этого проекта; если файл уже лежит на сайте — на сайт, иначе на GitHub.
- **Новая версия** берётся из `app-test.json` в ветке агента (`IVA_TEST_FEED`). Его пишет сборка (`build-apk.yml`) вместе с новым APK. Уже выпущенный `ProkatInstrumenta-<версия>.apk` сборка **не перезаписывает** — для изменений поднимите `NEW_NAME`/`NEW_CODE`.
- **Новая ветка агента → поменять имя ветки в `IVA_TEST_FEED`** (`assets/app-release.js`) и в ссылке `apk` в `app-test.json` — только эти два места. В `build-apk.yml` имя ветки больше не прописано (запуск на `arena/**`, шаг коммита срабатывает на любой ветке, кроме `main`). Забыть не даст сторож `tests/app-test-channel.cjs`: он сверяет ветку в обеих строках и проверяет, что такая ветка есть на сервере (`git ls-remote`; без сети проверка честно пропускается).
- Отменить последний релиз (у всех снова предыдущая): `delete from public.app_releases where version_code = (select max(version_code) from public.app_releases);` — в SQL Editor.
- Скрытие, а не защита: репозиторий публичный, тестовый APK можно скачать по прямой ссылке.
- `app-update.json` (самообновление внутри приложения) этим механизмом не меняется.
- Сторожа: `tests/app-test-channel.cjs`, `tests/syntax-and-release.cjs`, браузерные `tests/app-banner.cjs`, `tests/chief-and-apk.cjs`; стенд базы `tools/app-releases-stand.py`.
