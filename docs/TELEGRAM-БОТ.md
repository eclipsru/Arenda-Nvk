# Telegram-бот «Ивы» — где живёт, что делает, как управлять

Обновлено: 03.10.2026. Источник — диагностика боевой базы (`tools/diag-owner.sql`, `tools/diag-bot.sql`), см. `docs/ЖУРНАЛ.md`.

## Где живёт
**Прямо в базе Supabase**, без отдельного сервера и без функций Supabase (Edge Functions):
- функции `public.iva_tg_*` — SQL-код бота (полный текст: `supabase/bot/iva_tg_snapshot_20261003.sql`);
- отправка в Telegram — через расширение базы `pg_net` (исходящие запросы);
- токен бота — в таблице `public.iva_secrets` (строка `BOT_TOKEN`); посетителю сайта таблица **недоступна** (проверено 03.10.2026);
- кому слать — таблица `public.iva_tg_targets`: `owner` — владелец, `admin:<почта>` — пункт проката;
- кто писал боту — таблица `public.iva_tg_chats` (нужна, чтобы привязать чат).

Кода бота в сайте нет и не нужно: база сама шлёт сообщение, когда в таблице появляется строка.

## Что делает
| Событие в базе | Кому | Что приходит |
|---|---|---|
| Пункт проката взял заявку (`order_parts`, новая строка) | владельцу | номер заявки, состав, кто взял, комиссия, ссылка в кабинет |
| то же | пункту проката (если его чат привязан) | номер заявки, состав, ссылка в кабинет |
| Статус заявки изменился (`order_parts`, изменение) | владельцу | номер, «было → стало», состав |
| Новая анкета арендодателя (`landlord_applications`) | владельцу | город, регион, категории, число инструментов, ссылка в кабинет |

**Контакты клиента и заявителя в Telegram не отправляются** (решение владельца №17) — после применения
`supabase/migrations/20261003_bot_no_contacts.sql`. До применения в сообщения попадали имя и телефон клиента,
ФИО, телефон, email и компания заявителя.

Рядом, но **не Telegram** (тоже из базы):
- новая заявка (`orders`) → функция Supabase `order_to_max` → мессенджер **MAX**. До правки уходила вся строка заявки с контактами; после `supabase/migrations/20261003_max_no_contacts.sql` — только номер, состав, срок, дата и ссылка в кабинет (решение владельца 03.10.2026: «MAX — как Telegram»). Откат — `supabase/bot/max_rollback_20261003.sql`;
- новое объявление (`tools`, `services`) → функция Supabase `vk_wall_post` → стена **ВКонтакте** (без персональных данных).

## Как проверить, что работает (2 команды, SQL Editor)
1. `select public.iva_tg_test();` → в Telegram придёт «🤖 Ива: тест…».
2. Через 10 секунд, отдельным Run: `select public.iva_tg_status();` → «✅ Telegram принял сообщение».

## Как «перезапустить», выключить, сменить токен
| Нужно | Команда в SQL Editor |
|---|---|
| Бот молчит | сначала проверка выше; если `iva_tg_status` пишет «канал pg_net не работает» — Database → Extensions → pg_net → выключить и включить |
| Временно выключить уведомления владельцу | `update public.iva_tg_targets set active = false where key = 'owner';` |
| Включить обратно | `update public.iva_tg_targets set active = true where key = 'owner';` |
| Сменить токен (если утёк) | в @BotFather: /revoke → новый токен → `select public.iva_setup_bot('НОВЫЙ_ТОКЕН');` — токен вводится только в SQL Editor, не в чат |
| Привязать чат пункта проката | пункт пишет боту /start → `select * from public.iva_tg_poll();` → `select public.iva_tg_link('admin:почта@пункта', CHAT_ID, 'Название');` |
