# Письма клиенту о заявке (П5)

Обновлено: 03.10.2026. Решение владельца: письма — клиенту; без своего домена — с ящика на mail.ru.

## Как устроено
1. Клиент (вошедший в аккаунт) оформляет заявку → в `order_parts` появляются строки → триггер `trg_iva_email_part`
   ставит письмо в очередь `iva_email_jobs` (одно на заявку) и будит функцию Supabase `order_email` (через `pg_net`).
2. Пункт проката жмёт «Выдал» (`rented`) или «Вернули» (`closed`) → ещё по письму.
3. Функция `order_email` по одноразовому пропуску получает из базы адрес и текст (`iva_email_take`), отправляет
   через `smtp.mail.ru:465` и записывает итог (`iva_email_done`).

Код: `supabase/migrations/20261003_order_email.sql`, `supabase/functions/order_email/index.ts`. Сторож: `tests/p5-order-email.cjs`.

## Защита
- Пропуск на каждое письмо свой, срабатывает один раз, живёт сутки. Без него функция ничего не отправит;
  адресата и текст снаружи задать нельзя — они берутся из базы.
- В очереди писем нет email и имён — только номера; адреса из текстов ошибок вырезаются; в журнал функции адреса не пишутся.
- Сбой почты не мешает сохранить заявку и сменить статус.
- Пароль ящика — «пароль для внешних приложений» mail.ru, хранится только в Supabase → Edge Functions → Secrets.

## Проверить, что письма уходят
```sql
select id, kind, order_id, status, err, created_at from public.iva_email_jobs order by id desc limit 10;
```
- `sent` — письмо принято mail.ru; `skipped` — заявка гостя без email (так и должно быть);
- `failed` + «535 …» — неверный пароль приложения (пересоздать в mail.ru и обновить секрет `SMTP_PASS`);
- `pending` долго — функция не вызвалась: проверить, что она называется ровно `order_email` и у неё выключена проверка JWT.

## Выключить письма
Отключить триггер (данные не удаляются, только с согласия владельца):
`DROP TRIGGER IF EXISTS trg_iva_email_part ON public.order_parts;`
Или мягко — удалить секрет `SMTP_PASS`: письма будут копиться как `failed`.

## Ограничения
- Письма получают только заявки из аккаунта (у гостевых заявок нет email).
- У личного ящика mail.ru есть суточный лимит отправки (точная цифра агентом не проверена); на текущем объёме заявок хватает с запасом.
  Когда появится свой домен — перейти на почтовый сервис с API (план — в журнале).
