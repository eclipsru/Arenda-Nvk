**Что сделано в рамках этапа:**
- `tools/check.sh` — предполётная проверка: окружение, секреты, релиз приложения, статические тесты, браузерные тесты (если Playwright установлен), локальный сервер поднимается и гасится автоматически;
- `tools/check-release.js` — сверка `app-update.json` ↔ файл APK ↔ эталонный sha256 в тесте;
- `tools/snapshot.sh` — снимок состояния в `.snapshots/` + локальный тег точки отката;
- `tools/screenshot-baseline.js` + `tools/screens-baseline.json` — эталонные скриншоты 12 страниц × 3 ширины;
- `docs/BACKUP-SUPABASE.md` — бэкап базы (pg_dump и вариант без установки), включая способ получить baseline-схему, потому что в репозитории базовая схема отсутствует;
- `docs/KEYSTORE-PASSWORD-ROTATION.md` — смена пароля ключа подписи без смены сертификата + удаление пароля из `APK-ИНСТРУКЦИЯ.md`;
- `docs/README-DEV.md` — памятка: проверки, откаты, запреты;
- `package.json` (служебный, на сайт не влияет), обновлённый `.gitignore` (снимки, бэкапы, venv);
- **`tools/backup-windows.ps1`** — бэкап базы под Windows «в одну команду»: находит `pg_dump`, спрашивает строку подключения, делает полный/схемный/данные-дампы, проверяет их, с флагом `-Baseline` кладёт структуру базы в репозиторий; если `pg_dump` нет — подсказывает установку и запасной путь;
- **`tools/rotate-keystore-windows.ps1`** — смена пароля ключа подписи под Windows: запоминает отпечаток сертификата, создаёт копию с новым паролем, сверяет отпечаток, по возможности проверяет подпись на APK; при несовпадении — останавливается.

**Проверено на практике (не «на глаз»):**
- синтаксис обоих PowerShell-скриптов — проверен парсером PowerShell 7.4 (0 ошибок);
- ветки подсказок при отсутствии `pg_dump` / `keytool` — проверены запуском;
- последовательность смены пароля keytool — проверена на тестовом ключе: отпечаток сертификата **совпал до символа**, старый пароль к новому файлу не подходит, новый работает;

### ЭТАП П0 — дополнение от 30.09.2026: бэкап без установки программ

**Причина:** у владельца `winget install -e --id PostgreSQL.PostgreSQL.16` падает с ошибкой 403 (баг winget, не блокировка) — обычный путь установки `pg_dump` не сработал.

**Что добавлено (ветка `work/p0-pgdump-fix`, Pull Request №4):**
- `tools/schema-dump.sql` — запрос для SQL-редактора Supabase: выгружает **структуру** базы (таблицы, ограничения, индексы, функции, триггеры, правила доступа) одним текстом. Ничего скачивать и устанавливать не нужно;
- `tools/backup-api-windows.ps1` — выгрузка **данных** всех таблиц через REST API Supabase в файлы `.ndjson` + `manifest.json`, с постраничной выгрузкой и сверкой количества записей с базой;
- `tools/backup-windows.ps1` — доработан: ищет распакованный (портативный) `pg_dump`, принимает `-PgBin`, при отсутствии утилиты подсказывает четыре пути вместо одной команды `winget`;
- `docs/BACKUP-SUPABASE.md`, `docs/README-DEV.md` — обновлены.

**Проверено на практике:**
- `tools/schema-dump.sql` прогнан на живом PostgreSQL 17: структура снята → восстановлена в чистую базу → **состав совпал до объекта** (таблицы 6/6, индексы 10/10, функции 3/3, триггер 1/1, политики 3/3, последовательности 5/5); после восстановления работают триггер, RPC-функция и правила доступа;
- `tools/backup-api-windows.ps1` проверен на стенде-заглушке: 2500 записей выгружены тремя страницами, таблица без колонки `id` обработана отдельным путём, количество сверено, кириллица и JSON не повреждены, файлы без BOM; отдельно проверены «плохой ключ» (понятная ошибка 401) и недоступный адрес;
- синтаксис всех трёх PowerShell-скриптов — 0 ошибок парсера (PowerShell 7.4);
- версии архивов EnterpriseDB доступны: `postgresql-17.7-1-windows-x64-binaries.zip` — 316 МБ, код 200.

**Что может сломаться / ограничения:**
- выгрузка через API не забирает файлы из хранилищ (`tool-photos`, `voice`) — в базе только записи о них;
- выгрузка через API не снимает структуру — её даёт `tools/schema-dump.sql`;
- восстановления из `.ndjson` пока нет — напишу отдельным скриптом, когда появится задача (нужен для переноса на `iva-staging`).

**Как откатить:** `git revert` коммита из Pull Request №4 (или удалить перечисленные файлы) — сайт, база и релизы приложения не затрагиваются.
