# Оплата комиссии через ЮKassa (приложение 10.133)

Админ проката оплачивает комиссию площадки онлайн прямо из приложения. Деньги идут в **вашу** ЮKassa.
Решения владельца (04.11.2026): платят только комиссию; кнопка — только в приложении; сумма любая (по умолчанию —
весь долг); чеки самозанятого вы пробиваете сами в «Мой налог».

## Как это работает

1. Админ: «Кабинет» → карточка «Комиссия владельцу» → **«Оплатить»** → сумма → **«Оплатить через СБП»**
   (с 10.135; ниже — ссылка «Другой способ (карта, SberPay)»).
2. Сервер (функция Supabase `iva-pay`) создаёт платёж в ЮKassa, приложение открывает страницу оплаты ЮKassa.
   «Оплатить через СБП» — сразу страница СБП (на телефоне — список банков, дальше — приложение банка), без выбора
   способа. «Другой способ» — обычная страница (СБП, карта, SberPay…). Данные карты в приложение не попадают.

   **СБП должна быть включена в магазине ЮKassa** (личный кабинет → «Способы оплаты»). Если не включена — сервер сам
   откроет обычную страницу, а приложение напишет «СБП в ЮKassa пока не включена — открыта обычная страница оплаты».
   Сразу открыть приложение банка, минуя список банков, ЮKassa при нашей интеграции не даёт: для СБП документирован
   только переход на её страницу (сценарий redirect).
3. После оплаты ЮKassa присылает уведомление; сервер **сам спрашивает у ЮKassa** статус платежа и только при
   «оплачено» записывает в `fee_payments` подтверждённую оплату (как подтверждённую вами вручную). Долг уменьшается сам.
   Приложение тоже спрашивает итог (если уведомления не настроены — оплата всё равно засчитается, пока открыто приложение
   или при следующем входе в «Кабинет»).
4. Вы: «Управление» → «Комиссия» → **«Онлайн-оплаты ЮKassa»** — кто, сколько, когда, номер ЮKassa и способ.
   Пробили чек в «Мой налог» и отправили админу на почту — нажмите **«Чек пробит»**. Сверху видно, сколько чеков осталось.

Оплата переводом с «Я оплатил — отправить» на сайте работает как раньше.

## Что сделать (один раз)

1. **SQL.** Supabase → SQL Editor → New query → вставить весь `supabase/migrations/20261123_yookassa_fee.sql` → Run.
   Все 4 строки проверки — «✅» (последняя пробует записать оплату и сразу откатывает — в базе ничего не остаётся).
2. **Ключи ЮKassa — в секреты GitHub** (не в чат): github.com/eclipsru/Arenda-Nvk → Settings → Secrets and variables →
   Actions → New repository secret:
   - `YOOKASSA_SHOP_ID` — shopId из личного кабинета ЮKassa (Интеграция → Ключи API), только цифры;
   - `YOOKASSA_SECRET_KEY` — секретный ключ оттуда же (`test_…` — тестовый магазин, `live_…` — боевой).
   Начать лучше с тестового магазина: в приложении будет написано «тестовый режим», деньги не списываются.
3. **Влить PR.** Функции выкладываются в Supabase из `main` (задача «Выкладка функций Supabase»); она же переносит
   ключи ЮKassa из GitHub в Supabase. В итоге задачи — «ключи ЮKassa: да».
4. **Уведомления ЮKassa:** личный кабинет ЮKassa → Интеграция → HTTP-уведомления → URL
   `https://wdxdeatphizclskfmfxi.supabase.co/functions/v1/iva-pay`, события `payment.succeeded` и `payment.canceled`.
5. Проверка: `https://wdxdeatphizclskfmfxi.supabase.co/functions/v1/iva-pay` в браузере → `{"ok":true,"ready":true,…}`.

Пока шагов 1–3 нет, «Оплатить» отправляет запрос владельцу площадки, как раньше (оплата переводом).

## Если ЮKassa отказала (06.11.2026)

Сайт и приложение показывают причину по-русски и номер ошибки ЮKassa (на сайте — с кнопкой «Копировать»; номер
просит поддержка ЮKassa). Последняя неудачная попытка видна над «Историей оплат» на этом устройстве, пока оплата не
пройдёт или её не скроют. В базе причина остаётся в `iva_yk_pay.cancel_reason`: код и описание ЮKassa, номер ошибки и
состояние магазина.

| Ответ ЮKassa | Что видит админ | Что делать владельцу площадки |
| --- | --- | --- |
| 403 `forbidden` («Transaction forbidden») | «ЮKassa запретила платежи в магазине площадки» + состояние магазина (функция сама спрашивает `GET /v3/me`: отключён / нет способов оплаты / включён) | Кабинет ЮKassa: статус магазина, документы, договор, способы оплаты; если всё зелёное — поддержка ЮKassa с номером ошибки |
| 401 `invalid_credentials` | «ЮKassa не приняла ключи магазина» | Проверить `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`: ключ выпущен в этом же магазине |
| 404 | «ЮKassa не нашла магазин» | Проверить `YOOKASSA_SHOP_ID` |
| 400 `invalid_request` | «ЮKassa отклонила платёж (поле …)» | Обычно сумма или способ оплаты; при повторе — поддержка ЮKassa |
| 429 | «Попробуйте через минуту» | — |
| 5xx / нет ответа | «ЮKassa временно не отвечает» | Подождать |

Последние отказы в базе (SQL Editor, только чтение):

```sql
select id, admin_email, amount, created_at, cancel_reason
from public.iva_yk_pay
where status = 'canceled'
order by id desc
limit 20;
```

## Чеки

ЮKassa с 29.12.2025 не оформляет чеки самозанятых. На каждую онлайн-оплату пробейте чек в «Мой налог»:
услуга «Комиссия площадки «Ива»», сумма и дата оплаты из списка; если админ — ИП или организация, укажите его ИНН.

## Безопасность

- Ключи ЮKassa — только в секретах GitHub/Supabase, в коде и журналах их нет.
- Засчитывает только сервер по ответу ЮKassa на свой запрос; поддельное уведомление ничего не засчитает;
  повтор уведомления не удваивает оплату.
- Таблицу онлайн-оплат админ видит только свою, вы — все; писать в неё напрямую не может никто.
- Сумма 1–100 000 ₽, не больше 5 незавершённых попыток за 10 минут.

## Откат

- Приложение: `git revert` коммита 10.133 (кнопка пропадёт).
- База: `supabase/migrations/20261123_yookassa_fee_rollback.sql` — уберёт таблицу онлайн-оплат; уже засчитанные
  оплаты останутся в `fee_payments` (перед откатом выгрузите список для чеков: `select * from public.iva_yk_pay order by id;`).
- Функция: удалить секреты `YOOKASSA_*` в GitHub и Supabase — функция ответит «не подключено».
