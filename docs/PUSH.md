# Мгновенные уведомления админам (Firebase, 10.74)

Решение владельца 14.10.2026: уведомления о новых сообщениях и заявках должны приходить **сразу, даже когда
приложение закрыто** — через Firebase, **только админам**. У клиентов всё как было (проверка раз в ~15 минут).
Это решение отменяет «без Firebase» от 13.10 — только для админов.

## Как это работает

1. Клиент пишет админу или оформляет заявку на его инструмент → база (триггер) ставит сигнал в очередь
   и будит функцию Supabase `iva-push`.
2. Функция шлёт через Firebase на телефон админа **сигнал «проверь сейчас»**: в нём только буква
   `m` (сообщение) или `o` (заявка). Ни текста, ни имён, ни телефонов через Google не идёт.
3. Телефон просыпается, приложение обычным запросом забирает новое и показывает то же уведомление, что и раньше —
   с расписанием 10.73, переключателями и памятью «уже показано» (дважды не придёт).

Если у телефона нет сервисов Google или Firebase ещё не настроен — всё работает как в 10.73 (раз в ~15 минут).
Состояние видно в приложении: «Профиль» → «Настройки» → «Уведомления», строка «Мгновенные уведомления: …».

## Что сделать владельцу (один раз, ~15 минут)

### 1. Проект Firebase
1. Откройте https://console.firebase.google.com → «Создать проект» (название любое, например «Ива»).
   Google Analytics можно выключить.
2. В проекте: значок Android («Добавить приложение» → Android).
   **Имя пакета: `ru.prokatnvsk.app`** (ровно так). Остальные поля можно не заполнять.
3. Скачайте файл **`google-services.json`** (кнопка на шаге 2 мастера). Дальше в мастере — «Далее» до конца,
   ничего в приложение добавлять не нужно.
4. ⚙ «Настройки проекта» → вкладка «Сервисные аккаунты» → «Создать закрытый ключ» → скачается JSON-файл ключа.
   **Это секрет**: никому не пересылайте, в чат не вставляйте.

### 2. Секреты GitHub (агент их не видит)
GitHub → репозиторий → Settings → Secrets and variables → Actions → New repository secret:
- `FCM_GOOGLE_SERVICES` — всё содержимое файла `google-services.json`;
- `FCM_SERVICE_ACCOUNT` — всё содержимое JSON-файла ключа из шага 1.4.

### 3. Выложить функцию
GitHub → Actions → «Выкладка функций Supabase» → Run workflow → в списке веток выберите
`arena/1da7609b-arenda-nvk` → Run. Через 1–2 минуты в итоге запуска: «✔ iva-push … секреты Firebase: да».
(После слияния ветки в `main` функция выкладывается сама.)

### 4. SQL
Supabase → SQL Editor → New query → вставить весь текст `supabase/migrations/20261014_push_admins.sql` → Run.
Внизу таблица — все строки «✅».

### 5. Телефон
Установить 10.74, войти админом, открыть приложение на минуту. В «Настройки» → «Уведомления» должно стать
«Мгновенные уведомления: подключены». Проверка: закрыть приложение (смахнуть из недавних), с другого
аккаунта написать этому админу — уведомление придёт за несколько секунд.

## Если не подключилось
| Строка в настройках | Что значит |
|---|---|
| «владелец ещё не настроил Firebase» | нет секретов или функция не выложена (шаги 2–3) |
| «сервер ещё не готов (нужен SQL)» | не применён SQL (шаг 4) |
| «на телефоне нет сервисов Google» | телефон без Google (Huawei/Honor новые) — работает раз в ~15 минут |
| «не подключились (…)» | в скобках код ошибки; нажмите на строку — повторит сразу. Пришлите код агенту |

## Откат
- Отключить сигналы (данные не удаляются):
  ```sql
  DROP TRIGGER IF EXISTS trg_iva_push_msg ON public.app_messages;
  DROP TRIGGER IF EXISTS trg_iva_push_part ON public.order_parts;
  ```
- Приложение: `git revert` коммитов 10.74 и новая сборка с номером выше (Android не ставит меньшую версию).
- Секреты Firebase можно удалить в GitHub и Supabase (Edge Functions → Secrets); ключ сервисного аккаунта —
  отозвать в Firebase → Настройки проекта → Сервисные аккаунты.

## Устройство (для разработчика)
- Приложение: `android/patches/IvaPushPatch.java` — без библиотек Firebase (сборка идёт из готового APK 10.14):
  Firebase Installations по REST, токен FCM у сервисов Google тем же способом, что Firebase SDK
  (`bindService` к `com.google.android.c2dm.intent.REGISTER` + Messenger; сверено с microG и firebase-messaging
  `GmsRpc`). Приёмник `IvaPushPatch$Rx` в манифесте — `android/patches/axml_push.py`.
- Сервер: `supabase/functions/iva-push/index.ts` (FCM HTTP v1, подпись RS256 через WebCrypto),
  `supabase/migrations/20261014_push_admins.sql` (токены, очередь с одноразовыми пропусками, триггеры).
- Проверки: `IvaPatchTest` (push 10.74), `tests/iva-push.cjs`, блок 10.74 в `tests/apk-build-guard.cjs`.
