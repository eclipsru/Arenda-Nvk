# Смена пароля ключа подписи приложения (keystore) — без смены сертификата

## Зачем

Ключ подписи приложения (`prokat-new.p12`, alias `prokat`) — это «паспорт» приложения в Android. Правило Android: обновление устанавливается поверх старой версии только если оно подписано **тем же сертификатом**. Поэтому сертификат менять нельзя, а вот **пароль — можно и нужно**: ранее он был опубликован в открытом файле `APK-ИНСТРУКЦИЯ.md` (уже удалён в этом же этапе).

**Ключевое:** смена пароля не меняет сертификат. Все будущие APK по-прежнему встают «поверх» — обновления у пользователей не ломаются. Проверяем это отпечатком (ниже).

---

## Что понадобится

- Файл keystore `prokat-new.p12` (лежит у вас вне репозитория).
- **Старый** пароль (тот, что был) и придуманный **новый** (12+ символов, лучше из генератора паролей).
- Java (для `keytool`) — есть в составе JDK; или Android Studio. Проверка: `keytool -help` в терминале.
- Желательно: Android SDK build-tools для `apksigner` (для финальной проверки). Если нет — проверим отпечатком через `keytool`+`openssl`.

> 🙅 Не публикуйте новый пароль в GitHub, в документах, в чатах и в задачах. Место пароля — менеджер паролей + зашифрованная резервная копия (2 места).

---

## Шаг 1. Зафиксируйте отпечаток сертификата ДО смены пароля

Windows (PowerShell) / macOS / Linux — команда одна:
```bash
keytool -list -v -keystore prokat-new.p12 -storetype PKCS12 -alias prokat -storepass СТАРЫЙ_ПАРОЛЬ
```
Найдите строку вида:
```
Certificate fingerprints:
	 SHA256: 8A:D9:D6:A9:...  (запишите/скопируйте это значение)
```
**Это ваш контрольный отпечаток.** После смены пароля он обязан быть точно таким же.

---

## Шаг 2. Создайте копию с новым паролем

```bash
keytool -importkeystore \
  -srckeystore prokat-new.p12 -srcstoretype PKCS12 -srcalias prokat -srcstorepass СТАРЫЙ_ПАРОЛЬ \
  -destkeystore prokat-new-rotated.p12 -deststoretype PKCS12 -destalias prokat \
  -deststorepass НОВЫЙ_ПАРОЛЬ -destkeypass НОВЫЙ_ПАРОЛЬ
```
- Новая копия — отдельным файлом (`prokat-new-rotated.p12`). Старый файл пока не удаляем: сначала проверяем.
- Если `keytool` ругается на формат (JKS/PKCS12): добавьте `-J-Dkeystore.pkcs12.legacy=false` или используйте свежий JDK 17+.

---

## Шаг 3. Проверьте, что сертификат не изменился

```bash
keytool -list -v -keystore prokat-new-rotated.p12 -storetype PKCS12 -alias prokat -storepass НОВЫЙ_ПАРОЛЬ
```
**SHA256 из вывода должен совпадать с отпечатком из шага 1, до символа.**
Если совпал — всё хорошо: это тот же сертификат, просто с новым паролем.

Проверка без Java (если есть `openssl`):
```bash
openssl pkcs12 -in prokat-new-rotated.p12 -passin pass:НОВЫЙ_ПАРОЛЬ -nokeys -clcerts \
 | openssl x509 -noout -fingerprint -sha256
```

---

## Шаг 4. Проверьте подпись на реальном APK

Скачайте актуальный `ProkatInstrumenta-10.14.apk` из репозитория и проверьте им, что SDK принимает новый keystore:
```bash
apksigner sign --ks prokat-new-rotated.p12 --ks-key-alias prokat \
  --ks-pass pass:НОВЫЙ_ПАРОЛЬ --key-pass pass:НОВЫЙ_ПАРОЛЬ \
  --out test-signed.apk ProkatInstrumenta-10.14.apk

apksigner verify --print-certs test-signed.apk
```
Что должно быть в выводе:
- `Verifies` (подписи v1/v2/v3 валидны);
- в `Signer #1 certificate SHA-256 digest` — **тот же отпечаток**, что в шаге 1;
- имя файла `test-signed.apk` — просто проверочный, выкладывать его не надо. Удалите после проверки.

Если `apksigner` не установлен, шаг можно пропустить: следующая сборка APK всё равно проверится перед публикацией.

---

## Шаг 5. Замените рабочий файл и обновите хранение

1. Переименуйте `prokat-new-rotated.p12` → так, как у вас принято хранить рабочий keystore (например, остаётся отдельная папка сборки).
2. **Старый** файл с прежним паролем — удалите (или положите в архив и забудьте пароль от него; лучше удалить, чтобы не путать).
3. Пароль записать в менеджер паролей (Bitwarden/KeePass/1Password) в запись «Ива · ключ подписи Android».
4. Сделать **две** резервные копии keystore (флешка + облако, зашифрованно) — потеря keystore означает невозможность обновлять приложение в Android вообще.

---

## Шаг 6. Никаких паролей в репозитории

- Пароль в документации/коде не пишем никогда. В `APK-ИНСТРУКЦИЯ.md` уже удалён (этим же этапом), проверка автоматическая: `bash tools/check.sh` (раздел «Секреты»).
- Для сборки на будущее: пароль вводится вручную либо передаётся через переменные окружения/секреты сборочной машины (`KS_PASS`), никогда не в файле.
- Если собираете в GitHub Actions (не обязательно): пароль — в GitHub Secrets, а keystore — в base64-секрете; я подготовлю такую сборку отдельно, если решишь.

## Что изменилось для будущих сборок

Ничего, кроме пароля:
1. Собери APK тем же пакетом и `versionCode`+1.
2. Подпиши **тем же сертификатом** (файл с новым паролем).
3. Обнови `app-update.json` (versionCode, versionName, ссылка на файл).
4. Прогони `bash tools/check.sh` — он проверит, что хеш APK и `app-update.json` согласованы, и что версии совпадают с тестами.
