# Как быстро и безопасно править «Иву»

Памятка для владельца и агента: где что менять, какие команды запускать и что
проверить перед Pull Request. Все команды — в папке проекта. На Windows — в Git Bash
(или через `npm run ...` в PowerShell).

---

## 1. Быстрый цикл: 4 шага

```bash
npm run dev            # 1. открыть предпросмотр: http://localhost:8080
# 2. править файлы — страница перезагрузится сама
npm run check:fast     # 3. быстрая проверка, ~3 секунды
npm run check          # 4. полная проверка перед PR (браузерные тесты — в CI)
```

`npm run dev` ничего не публикует: он показывает сайт с вашего компьютера и
перезагружает страницу после каждого сохранения. Кэш браузера отключён, поэтому
вы всегда видите свежую версию.

Если открываете сайт с телефона в той же Wi-Fi сети — сервер напечатает адрес
вида `http://192.168.…:8080/`.

## 2. Что где менять

| Что нужно изменить | Где менять | После правки |
|---|---|---|
| Внешний вид всех страниц (цвета, кнопки, отступы) | `assets/theme.css` | `npm run assets:bump -- assets/theme.css 20261017-rel` |
| Шапка, меню, поиск, карточки, баннер приложения | `assets/app.js` | `npm run assets:bump -- assets/app.js 20261017-rel` |
| Вход, база, объявления, избранное | `assets/sb.js` | `npm run assets:bump -- assets/sb.js 20261017-rel` |
| Главная | `index.html` | — |
| Каталог и фильтры | `catalog.html` | — |
| Карточка инструмента | `tool.html` | — |
| Подача объявления | `new.html` | — |
| Кабинет арендатора/арендодателя | `account.html` | — |
| Настройки профиля клиента | `profile.html`, `assets/client-profile.js` | `npm run assets:bump -- assets/client-profile.js 20261017-rel` |
| Чат | `chat.html` | — |
| Админка каталога | `admin.html` | — |
| Кабинет руководителя | `chief.html` | — |
| Приложение (внутренний экран) | `cabinet.html` | — |
| Тексты оферты, правил, политики | `offer.html`, `partner-terms.html`, `partner-privacy.html`, `privacy.html` | — |
| Страницы городов | `tools/city_template.html` и `tools/build_city_pages.py` | `python3 tools/build_city_pages.py` |
| Версия и сборка APK | `.github/workflows/build-apk.yml` (`NEW_NAME`, `NEW_CODE`) | push в ветку `arena/**` или кнопка Run workflow |
| База данных | `supabase/migrations/*.sql` | применяет владелец в SQL-редакторе Supabase |

**Страницы городов руками не правим.** `city/*.html` — сгенерированные файлы.
Правка в них пропадёт при следующей сборке. Меняем шаблон или генератор и запускаем
`python3 tools/build_city_pages.py`.

**Большие страницы.** `admin.html`, `chief.html`, `account.html`, `cabinet.html`,
`tool.html`, `new.html` — это один файл, где HTML, CSS и JS лежат вместе. Чтобы
не искать нужное место по всему файлу:

```bash
npm run map -- cabinet.html
```

Команда покажет номера строк и размеры блоков `<style>` и `<script>`, а также
основные функции в каждом блоке.

## 3. Метки кэша: одна команда вместо 80 файлов

Браузер запоминает CSS и JS. Чтобы после правки он взял новый файл, в адресе стоит
метка `?v=…`. Раньше её меняли руками в 80+ страницах — и один раз забыли в шести.
Теперь так:

```bash
npm run assets:check
# показывает метки всех общих файлов и падает, если где-то расхождение

npm run assets:bump -- assets/theme.css 20261017-rel
# ставит новую метку во всех страницах, city/, шаблоне и генераторе
```

Метку можно любую из букв, цифр, точки и дефиса. Удобно брать дату и короткое
название правки: `20261017-menu`, `20261018-fix`.

Если меняли несколько общих файлов — поднимите метку у каждого. `bump-all` есть,
но он сбрасывает кэш у всех файлов сразу — используйте только для крупного релиза.

## 4. Проверки: какую когда запускать

| Команда | Что делает | Когда |
|---|---|---|
| `npm run check:fast` | секреты, релиз, 24 статических теста; ~3 с | после каждой правки |
| `npm run check:only -- photon` | только тесты, в имени которых есть `photon` | когда правите одно место |
| `npm run check:list` | список имён тестов | если не помните имя |
| `npm run check` | всё, включая стенды PostgreSQL и браузерные тесты | перед PR |
| `npm run assets:check` | метки кэша | после правки CSS/JS |
| `npm run apk:report` | сколько весят APK и что можно archived | перед решением о старых сборках |

Браузерные тесты локально запускаются, только если установлены Playwright и Chromium:

```bash
npm install
npx playwright install chromium
```

В GitHub Actions они запускаются всегда. Если локально браузера нет — это не ошибка:
`check` честно напишет «пропущено», а настоящую проверку сделает CI.

## 5. Предпросмотр

### На компьютере

```bash
npm run dev
# http://localhost:8080
```

### В чате с агентом

Попросите: «подними предпросмотр». Агент запустит сервер, и в браузере появится
живая ссылка на текущую ветку. Это быстрее, чем ждать слияния PR и обновления
GitHub Pages.

### После слияния

Сайт собирается из `main` на GitHub Pages автоматически. Обычно это 1–2 минуты.
Если изменений не видно — обновите страницу с `Ctrl+F5` (на телефоне — потяните
страницу вниз).

## 6. Что сейчас тормозит и как это ускорить

| Что | Сколько | Что делать |
|---|---|---|
| 97 файлов APK в корне | ~118 МБ, из них 91 старая тестовая сборка (~111 МБ) | `npm run apk:report`; старые сборки можно приложить к GitHub Release и убрать из сайта — история в git останется |
| 6 больших страниц со встроенным JS | ~475 КБ JS внутри HTML | `npm run map`; отдельный этап — вынести JS в `assets/pages/*.js`, тогда агент читает только скрипт, а не всю страницу |
| Ручные метки кэша | 80+ страниц | `npm run assets:bump` — одна команда |
| CI каждый раз скачивает Playwright | ~1–2 минуты | добавлен кэш npm и браузера в `.github/workflows/check.yml` |
| Браузерные тесты только в CI | 3–5 минут | локально можно запускать один тест: `npm run check:only -- photon` |
| Большой HTML трудно читать | до 270 КБ на файл | `npm run map -- admin.html` показывает, где какой блок |

**Про APK.** Каждая тестовая сборка остаётся файлом в репозитории. Это удобно для
отката, но 90 версий — слишком много. Отчёт показывает защищённые файлы (выпущенная,
текущая, кандидат, QR и восстановление) и старые. Решение об архиве принимает
владелец: файлы можно приложить к GitHub Release, а из сайта убрать. Код и история
при этом не теряются.

## 7. Правила, чтобы не сломать

1. **Дизайн не меняем без согласования.** Только `assets/theme.css` и существующие
   компоненты. Новые визуальные элементы — предложение, а не факт.
2. **`city/*.html` не правим руками** — только шаблон и генератор.
3. **APK не правим и не пересобираем вручную.** Сборка — GitHub Actions
   (`.github/workflows/build-apk.yml`), подпись — ключ №6 из секретов.
4. **Версии приложения не прописываем на страницах.** Их берут
   `app-update.json`, `app-test.json` и `assets/app-release.js`.
5. **Секреты не попадают в репозиторий и в чат.** Пароли, ключи, `service_role`,
   `.env` — только в секретах GitHub/Supabase.
6. **Миграции базы применяет владелец.** Только `create ... if not exists`,
   `add column if not exists`, `create or replace`; без `drop` и `truncate`.
7. **Один этап — одна ветка — один PR.** В `main` напрямую не коммитим.
8. **После правки — запись в `docs/ЖУРНАЛ.md`.** Чат закрывается, журнал остаётся.

## 8. Если работаете с агентом

Скопируйте короткий промт из `docs/ПРОМТ-БЫСТРОЙ-ПРАВКИ.md` и добавьте одну строку:
что именно нужно сделать. Агент сам поднимет предпросмотр, сделает правку, прогонит
`check:fast`, обновит метки кэша и покажет ссылку.

Что стоит попросить в ответе:

- ссылку на предпросмотр;
- что сделано и какие файлы изменены;
- чем проверено (точные цифры: пройдено / ошибок / пропущено);
- как откатить;
- что нужно от вас (или «ничего»).

---

## 9. Чек-лист перед Pull Request

- [ ] `npm run check:fast` — 0 ошибок.
- [ ] Если меняли `assets/*.css|js` — `npm run assets:bump` и `npm run assets:check`.
- [ ] Если меняли страницы городов — `python3 tools/build_city_pages.py`.
- [ ] Если меняли дизайн — согласовано с владельцем.
- [ ] Предпросмотр открыт, ключевые экраны прокликаны (в том числе на узком экране).
- [ ] В `docs/ЖУРНАЛ.md` добавлена запись: что, чем проверено, как откатить.
- [ ] PR создан из ветки `arena/…` в `main`, описание — по-русски.

## 10. Шпаргалка по командам

```bash
npm run dev                 # предпросмотр + автоперезагрузка
npm run check:fast          # быстрая проверка
npm run check               # полная проверка
npm run check:list          # список тестов
npm run check:only -- photon
npm run assets:list         # текущие метки кэша
npm run assets:check        # расхождения меток
npm run assets:bump -- assets/theme.css 20261017-rel
npm run apk:report          # вес APK и старые сборки
npm run map -- admin.html   # карта большой страницы
npm run snapshot            # снимок состояния перед этапом
npm run screens:check       # сравнить внешний вид со эталоном (нужен Playwright)
```

Полезное без npm:

```bash
git status --short          # что изменено
git diff --stat             # сколько строк изменено
git grep -n "текст" -- '*.html' 'assets/*.js'
gh pr checks                # состояние проверок PR
gh run view --log-failed    # причина упавшей проверки
```
