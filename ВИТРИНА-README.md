# Ива — витрина аренды инструмента

Классифайд в брендинге «Ива». Без сборки: HTML + CSS + JS, кладётся на GitHub Pages как есть.

## Страницы

```
index.html       Главная: поиск, категории, ленты
catalog.html     Каталог: фильтры, сортировка, чипы
tool.html        Карточка объявления (?id=…)
favorites.html   Избранное
new.html         Подача объявления — 5 шагов        (этап 2)
account.html     Кабинет: объявления, избранное, профиль (этап 2)
cabinet.html     Рабочий кабинет: заказы, корзина, чат
admin.html       Админка каталога
assets/
  theme.css      Дизайн-система
  data.js        Справочники и демо-данные (запасной вариант)
  sb.js          Supabase: вход, объявления, фото          (этап 2)
  app.js         Шапка, меню, избранное, поиск, фильтры
```

## Этап 1 — витрина

Поиск с подсказками, фильтры (цена, категория, подкатегория, город, состояние,
доставка), 4 сортировки, состояние фильтров в URL, избранное в localStorage,
галерея со свайпом, «Показать телефон», адаптив с нижним меню и шторками.

## Этап 2 — подача и кабинет

**Данные живые, из Supabase.** Витрина показывает реальные объявления из `tools`;
если база недоступна — остаются демо-объявления из `data.js`.

**new.html** — 5 шагов: категория → фото → описание → цена → получение.
Загрузка до 5 фото в бакет `tool-photos` со сжатием до 1280 px (JPEG 82%),
живой предпросмотр карточки, валидация по шагам, черновик в localStorage.

**account.html** — мои объявления с фильтром по статусу, смена статуса,
удаление с подтверждением, избранное, профиль, выход.

**Статусы:** `active` / `moderation` / `archived` — колонка `status` в `tools`.
Снятые и отправленные на модерацию не видны в каталоге.

**Доступ:** размещать может только пользователь из таблицы `admins`.
Проверка и в интерфейсе, и на уровне RLS: политика `tools_admin` не даст
записать объявление с чужим `owner_email`.
