# Подключение арендодателей — 23.09.2026

## Страницы
- Главная: симметричный статичный блок «Полезная информация», подробное окно и ссылка на регистрацию.
- `landlord-register.html`: отдельный вход/создание аккаунта и короткая анкета для самозанятых, ИП и компаний. Существующий аккаунт используется повторно.
- `chief.html#landlords`: заявки, ручные решения, назначение комиссии и лимита, история.
- `partner-terms.html`, `partner-privacy.html`: рабочие редакции правил и согласия. Тексты не заменяют юридическую проверку, в том числе требований к инфраструктуре хранения персональных данных.

## Порядок работы
1. Создание аккаунта само по себе НЕ создаёт запись `admins`.
2. Заявка записывается защищённой RPC `submit_landlord_application` со статусом `pending`. User ID и email берутся из доверенного контекста, а не из анкеты.
3. Только активный владелец может вызвать `review_landlord_application`.
4. Возврат на доработку/отказ требует комментария. Повторная подача обновляет ту же анкету и сохраняет историю.
5. При одобрении обязательно явно указать целый процент комиссии и лимит. В одной транзакции создаётся роль `admin` (не `chief`), сохраняются условия и решение.
6. Повторное решение и изменение уже обработанной заявки блокируются. Существующий, в том числе отключённый, профиль нельзя переоформить через эту форму.
7. Профиль и инструменты доступны через текущие кабинеты. Расширенный `cabinet.html` использует прежнюю отдельную сессию: может потребоваться вход с тем же email/паролем.

## База
Миграция `supabase/migrations/20260923_landlord_applications.sql` уже применена в рабочем проекте.
- Анкеты и события: SELECT только для самого заявителя и владельца. Прямые INSERT/UPDATE/DELETE для клиентских ролей запрещены.
- Запись и решения — только через проверяющие права RPC.
- Для `tools_admin` добавлена обязательная проверка действующей роли арендодателя: прежняя проверка только owner_email позволяла обойти модерацию.
- Убрана проверка роли по поиску email внутри произвольного JWT metadata; роль проверяется по `admins`.
- Изменение email, role, active, fee_pct, debt_limit в `admins` самим арендодателем запрещено. Обычные поля профиля по-прежнему редактируются.
- Действующие роли, объявления и расчёты сохранены; ВК и платёжные функции не изменялись.

## Проверки
- Реальные проверки SQL в откатываемой транзакции: отсутствие прав до одобрения, RLS, защита от самоодобрения и подмены JWT metadata, запрет прямой записи, доработка, повторная подача, отказ, одобрение с условиями, защита роли, журнал. Тестовые пользователи/анкеты не оставлены в базе.
- Браузерные проверки с подменой ответов API: регистрация/вход, отправка, восстановление статуса, доработка, повторная отправка, одобрение, мобильный интерфейс, симметрия панелей, окно «Подробнее» и закрытие Escape.
- Анонимные REST-запросы к анкетам и RPC отклоняются.

## Что сознательно не подключено
- Автоматическая проверка ИНН, реестров и телефона. Статус заявлен пользователем, проверяет владелец вручную.
- SMS, email-рассылка решений, внешние уведомления о новых анкетах. Статус обновляется на странице заявки; владелец видит счётчик при загрузке/обновлении раздела.
- Изменение глобальных настроек подтверждения email: используются текущие настройки Supabase Auth; также обработан сценарий подтверждения по письму.
- Паспорт, банковские реквизиты и точный адрес выдачи не запрашиваются в первичной анкете.
