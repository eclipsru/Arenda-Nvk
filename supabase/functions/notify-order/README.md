**Этап:** П5 (шаг 1). **Зачем:** владелец узнаёт о заявке сразу, а не когда откроет кабинет.

## Как устроено

```
клиент отправил заявку → строка в таблице orders
        ↓ вебхук базы (Database Webhook, событие INSERT)
функция notify-order → собирает сообщение → Telegram Bot API → чат владельца
```

Заявка сохраняется в базе **независимо** от функции: если Telegram недоступен, клиент всё равно
видит «Заявка принята», а заявка остаётся в кабинете.

## Секреты (задаются в Supabase → Edge Functions → Secrets, в репозиторий не попадают)

| Секрет | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather |
| `TELEGRAM_CHAT_ID` | чат владельца, куда слать заявки |
| `WEBHOOK_SECRET` | своя длинная строка **только латиницей и цифрами**; такая же в заголовке вебхука |

## Локальная проверка (без Supabase)

```bash
# 1. Заглушка Telegram (любой локальный сервер, отвечающий {"ok":true} на POST)
# 2. Запуск функции:
TELEGRAM_BOT_TOKEN="111:TEST" TELEGRAM_CHAT_ID="42" WEBHOOK_SECRET="test-secret-1" \
TELEGRAM_API_BASE="http://127.0.0.1:9099" IVA_NOTIFY_HOST="127.0.0.1" IVA_NOTIFY_PORT="8787" \
deno run --allow-net --allow-env supabase/functions/notify-order/index.ts

# 3. Имитация вебхука:
curl -s -X POST http://127.0.0.1:8787/ -H 'content-type: application/json' \
  -H 'x-webhook-secret: test-secret-1' \
  -d '{"type":"INSERT","table":"orders","record":{"id":1,"name":"Тест","phone":"89180001122","tools":"Перфоратор","days":2}}'

# 4. Тесты:  deno test tests/edge/
#    (в общем прогоне: bash tools/check.sh — раздел «4.1. Функция уведомлений в Telegram»)
```

## Поведение при сбоях

| Ситуация | Что происходит |
|---|---|
| Telegram ответил 429 или 5xx | повтор до 3 раз (уважаем `retry_after`) |
| Telegram недоступен / токен неверный | вебхук получает 502 и причину — видно в логах функции; заявка не теряется |
| Тот же заказ пришёл второй раз | второй раз не отправляем (пометка в `notify_log`) |
| `notify_log` недоступна (нет ключа, нет таблицы) | отправляем всё равно — тишина хуже дубля |
| Отправка не удалась | пометка снимается, следующая попытка может отправить снова |
| Запрос без верного `x-webhook-secret` | 401, ничего не отправляем — чтобы посторонний не слал ложные «заявки» |

## Откат

1. Supabase → Database → Webhooks → удалить вебхук (уведомления прекращаются сразу).
